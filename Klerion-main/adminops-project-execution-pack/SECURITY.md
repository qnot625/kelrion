# Security Policy

## Reporting a vulnerability

Do not open a public issue for suspected vulnerabilities or personal-data exposure. Report privately to the designated security contact:

`security@<your-domain>`

Replace this placeholder before the repository becomes public or the product enters pilot.

Include:

- Affected component and tenant context, without sharing unnecessary personal data.
- Reproduction steps or proof of concept.
- Potential impact.
- Suggested remediation if known.
- Safe contact details for follow-up.

## Handling

The security team will acknowledge, triage severity, contain risk, preserve evidence, communicate remediation and coordinate disclosure. Cross-tenant exposure, authentication bypass, privileged-access abuse and sensitive-data leakage are treated as critical.

## Supported versions

Before public release, publish the supported production versions and security-patch policy here.

## Safe research

Do not access, modify or retain data belonging to other users or tenants; disrupt service; perform social engineering; or publicly disclose before coordinated remediation.
